# Update System

In-app update architecture for **FMT** using **electron-updater** and **GitHub Releases**.

> **v1.0.2:** Packaged FMT uses the public GitHub Releases feed. `electron-updater` reads `resources/app-update.yml` (generated by electron-builder) and fetches `https://github.com/HashmatKhanSediqi/sameer-desktop-app/releases.atom` plus `latest.yml`. The repository **must be public**. End users do not need `GH_TOKEN`.

---

## 1. Overview

| Attribute | Value |
|-----------|-------|
| Product | FMT |
| Normal operation | Fully offline-first |
| Update source | GitHub Releases (`provider: github`, `private: false`) |
| Owner / repo | `HashmatKhanSediqi/sameer-desktop-app` |
| Channel | `latest` (`latest.yml`) |
| Customer data | Always local (SQLite) — never cloud |
| Update tool | `electron-updater` |
| Installer artifact | `FMT-Setup.exe` (+ `latest.yml` / blockmap from electron-builder) |
| Application files | `%LOCALAPPDATA%\Programs\FMT\` (NSIS `productName`) |
| User data | `%APPDATA%\CustomerAccounting\` |

The update system distributes **application binaries** — not customer accounting data.

---

## 2. Architecture

```
Settings → Update UI
        │
        ▼
preload window.api.update.*
        │
        ▼
IPC: update:getStatus | update:check | update:download | update:install
        │
        ▼
UpdateService (main)
  - semver compare (shared/semver)
  - electron-updater adapter (GitHub feed via app-update.yml)
  - states: idle | checking | upToDate | available | downloading | ready | error | unsupported
        │
        ▼ (install only)
BackupService.createPreUpdateBackup()  →  validated .cab under backups/pre-update/
        │
   ┌────┴────┐
 fail      success
   │         │
   ▼         ▼
 block    quitAndInstall()
 install
```

- **Dev / unpackaged:** state is `unsupported`.
- **Packaged:** auto-check after startup delay, then at most once per 24 hours.
- **Manual check:** Settings → Application updates.
- **No newer release:** state is `upToDate` ("You are up to date."). This is not an error.
- **Network / GitHub failure:** state is `error` ("Could not check for updates. You can keep using FMT offline."). Underlying errors are written to `%APPDATA%\CustomerAccounting\logs\app.log`.
- electron-updater `update-not-available` is mapped to `upToDate`, never to the offline error.

`UpdateService` does **not** call `setFeedURL()`. Packaged builds use electron-builder's generated `resources/app-update.yml`.

## 3. GitHub Release configuration

### Repository

Configured in:

- `package.json` → `build.publish` (`provider: github`, owner/repo, `private: false`, `releaseType: release`)
- `src/shared/constants/updateConfig.ts` (status snapshot + env overrides)
- Packaged `resources/app-update.yml` (generated at build time)

npm `"private": true` means "do not publish this package to npm". It is **not** GitHub visibility. The GitHub provider must stay `private: false`.

### Required public feed

electron-updater (GitHub provider, no token) fetches:

1. `https://github.com/HashmatKhanSediqi/sameer-desktop-app/releases.atom`
2. `https://github.com/HashmatKhanSediqi/sameer-desktop-app/releases/latest`
3. `https://github.com/HashmatKhanSediqi/sameer-desktop-app/releases/download/<tag>/latest.yml`
4. `FMT-Setup.exe` and `FMT-Setup.exe.blockmap` from the same release

If the repository is private, GitHub returns **404** to unauthenticated clients (`logged_in=no`). Settings then shows the offline update error. That is the v1.0.1 failure mode.

### Required release format

1. Create a **published** (not draft) GitHub Release whose tag matches semver, e.g. `v1.0.2`.
2. Upload **electron-builder** Windows artifacts from **that same build**:
   - `FMT-Setup.exe`
   - `latest.yml`
   - `FMT-Setup.exe.blockmap`
3. `latest.yml` must match the installer (version, filename, size, SHA512).
4. Release must be the GitHub **latest** production release (not pre-release unless that is intentional).

### How to publish

**Windows installer builds must run on Windows x64.** Do not build `FMT-Setup.exe` on Linux or macOS — native modules (`bcrypt`, `better-sqlite3`) cannot be cross-compiled reliably and will produce a broken installer.

Recommended:

```bash
npm run typecheck
npm test
npm run build:win   # Windows x64 only; verifies PE native modules after build
# Tag, push — GitHub Actions (windows-latest) attaches dist/FMT-Setup.exe, latest.yml, FMT-Setup.exe.blockmap
```

Or push a version tag (`v*`) and let `.github/workflows/release-win.yml` build on `windows-latest`.

Do not hand-edit `latest.yml`. Do not publish an installer from a different version than the tag.

### What packaged apps do **not** need

- End-user `GH_TOKEN` / `GITHUB_TOKEN`
- `setFeedURL()` at runtime
- A private GitHub provider

## 4. Update flow

1. **Check** — `autoUpdater.checkForUpdates()` (no auto-download).
2. **Available** — remote semver newer than current → UI shows download.
3. **Download** — user-triggered; progress via `download-progress`.
4. **Ready** — update staged locally.
5. **Install** — create + validate pre-update `.cab` backup; only then `quitAndInstall`.
6. **Post-update startup** — existing `%APPDATA%\CustomerAccounting\` DB remains; normal migrations + integrity checks run. Updater does **not** modify the database. `app.getPath("userData")` stays `%APPDATA%\CustomerAccounting\`.

---

## 5. Backup-before-update safety

Before `quitAndInstall`:

1. `BackupService.createPreUpdateBackup()` writes `FMT_PreUpdate_*.cab` under `backups/pre-update/`
2. Backup must complete and pass existing validation (manifest, signature, SQLite integrity)
3. Retention: last **5** pre-update backups
4. If backup fails → **install is blocked**; user is informed; app and DB unchanged

Uses the existing `.cab` format — no second backup format.

---

## 6. Data preservation

| Path | On update |
|------|-----------|
| `%LOCALAPPDATA%\Programs\CustomerAccounting\` | Replaced (application files) |
| `%APPDATA%\CustomerAccounting\` | Preserved (database, images, backups, settings, logs) |

NSIS `deleteAppDataOnUninstall: false`. No installer action deletes userData. Default admin remains `admin` / `admin123` unless the user changed it.

---

## 7. Offline / failure behavior

| Condition | Behavior |
|-----------|----------|
| No internet / GitHub down / private repo 404 | Check → `error` / checkFailed; app remains usable |
| No newer release | `upToDate` |
| Malformed / invalid version | `error` / invalidVersion; no install |
| Download failure / interrupt | `error` / downloadFailed; install not started |
| Backup failure before install | Install blocked (`UPDATE_BACKUP_FAILED`) |
| Update failure on startup path | Auto-check errors are swallowed; DB startup unaffected |

Update failures must **never** prevent FMT from starting or using the existing database.

---

## 8. Versioning

- Semantic versioning: `MAJOR.MINOR.PATCH`
- Same or older remote versions are not offered
- Invalid versions are rejected
- Source of truth for running version: `src/shared/constants/version.ts` / `package.json`

---

## 9. Security

- Uses electron-updater’s normal GitHub Releases + `latest.yml` checksum verification
- No custom download-and-run of arbitrary URLs
- Downgrades disabled (`allowDowngrade = false`)
- **Code signing:** Authenticode is **not** configured. `signAndEditExecutable` is `false`. Unsigned installers are **not** fully trusted by Windows SmartScreen.

## 10. IPC

| Channel | Purpose |
|---------|---------|
| `update:getStatus` | Current snapshot |
| `update:check` | Manual / programmatic check |
| `update:download` | Download available update |
| `update:install` | Safety backup then quitAndInstall |
| `update:status` (event) | Push status to renderer |

All invoke channels require an authenticated `sessionId`.

## 11. UI / localization

Settings → About → Application updates section shows current version, status, check / download / restart actions, progress, and errors.

Locales: English, Dari (`fa-AF`), Pashto (`ps`) — no hard-coded user-facing English strings.

## 12. Testing status

**Covered in automated tests:** semver compare, state transitions, no-update → upToDate, newer version → available, GitHub 404/network → error (not upToDate), unsupported development mode, download/downloaded states, backup-blocks-install, backup-before-install success path, GitHub `private: false` publish config, updater IPC, i18n keys, pre-update backup create/validate.

**v1.0.1 production failure (verified from installed logs):** `GET https://github.com/HashmatKhanSediqi/sameer-desktop-app/releases.atom` returned 404 with `logged_in=no`. Settings correctly showed the error state; the feed was not publicly readable.

**v1.0.2 live packaged verification (this machine, 2026-08-24):**
- Installed FMT v1.0.1 under `%LOCALAPPDATA%\Programs\FMT\`, user data `%APPDATA%\CustomerAccounting\`
- Update check detected GitHub Release **1.0.2** (`state: available`)
- Download of `FMT-Setup.exe` from GitHub completed (differential download)
- `createPreUpdateBackup()` wrote and validated `backups\pre-update\FMT_PreUpdate_2026-08-24_18-57-55.cab` (2 customers) before install
- After install, app started as **1.0.2**, opened the same `accounting.db`, auto-check reported up to date
- Persisted: customer `Updater Test Customer` (id 2, `hasPhoto: true`), Cash In 250 AFN, Cash Out 40 AFN (balance 210 AFN), currency `XYZ`, company `Updater Test Company`
- Admin login `admin` / `admin123` still worked

**v1.2.0 production failure (this machine, 2026-08-24):** Packaged **1.0.2** detected and downloaded **1.2.0**. Settings then showed "Update was not installed because the safety backup could not be completed." (`UPDATE_BACKUP_FAILED`). Logs: `Backup created` under `backups/pre-update/`, no `Pre-update backup created`, cab unlinked. Live `%APPDATA%\CustomerAccounting\data\accounting.db` has `schema_migrations` **1–8** (teller + dynamic currencies) and `PRAGMA integrity_check` is `ok`. Packaged 1.0.2 only ships migrations 001–006, so backup `assertSchemaCompatible` rejects schema 8 (`BACKUP_VERSION_MISMATCH`) and never calls `quitAndInstall`. 1.2.1 cannot patch already-installed 1.0.2; run `FMT-Setup.exe` once on that machine. After 1.2.1, in-app updates use silent NSIS (`quitAndInstall(true, true)` and installer `customInit` sets silent when `--updated` is present).

**Limitation (older builds):** `quitAndInstall(false, true)` with NSIS `oneClick: false` opens the FMT Setup wizard (`--updated` without `/S`). 1.2.1 treats `--updated` as silent and passes `/S` from the app.
